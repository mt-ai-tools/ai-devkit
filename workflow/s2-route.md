# Route

## Challenging a recommendation
When: the session or a subagent is about to recommend anything.
Do, check that:
- Leaner: all of it is needed.
- Tested: it passes the test in propose-dont-decide.
- Lasting: it is not a cheap way that costs more later.
- Checked: every claim is verified in the code.
- Rules: it keeps every rule, shape and convention.
- Standard: it is the industry's established way, and the way the code already solves the like elsewhere.

A recommendation that shapes a mechanism ends with one line, the standard:
the industry's way and the frame's own way for the like, and whether this
follows both. Where either can't be told without a search, the line says
"not sure" and why.

## Asking the operator
When: decisions.md gives a choice to the operator.
Do:
- Send up to 4 questions per message.
- Put each question whole in the message, every time it is asked, a
  repeat included: the question; the situation, with an everyday
  example; each option in plain words, with what it costs and what
  could go wrong; the recommended one, and why. Never point back to a
  brief, a decision number or an earlier message: the operator reads
  only this message.
- A change to written text shows its current words beside the
  proposed, item by item; an approval covers only what was shown.
- Give the full reasoning when the operator asks "why?".
- Once every answer is written down, no question is open and every
  check is green, carry on and say so in one line: a go asked for
  then only keeps the session waiting.
Don't:
- Don't ask the operator about a choice decisions.md leaves to the
  agents.
- Don't carry on into a brief's first step: approving a brief waits
  for the operator's go (s3-plan.md).

## Fixing small work
When: the session sorted new work as small.
Do:
- Send a fresh builder with the fix written down, and everything
  else the builder's own file asks for.
- Commit the fix.
- Report what changed, as short as it allows.

## Planning big work
When: the session sorted new work as bigger.
Do, by what it needs:
1. Big work to build now, or blocking the current brief:
   propose a brief to the operator, with a level, saying when the
   current brief must wait on it; on yes, at the level the
   operator names, the brief-writer writes it and adds it to the
   after list of each brief the yes names.
2. Anything else: write a draft at the level it needs.
Don't:
- Don't write a brief without the operator's yes.

# Where a line belongs

- A line of prose — in a rule, the workflow, an agent's file, a shape,
  convention, README, comment, plan or memory — earns its place only if
  missing it would let someone break something or undo a settled
  choice. It is short and factual.
- A line checked only by watching an agent work is about behaviour: at
  any moment, a rule; how work moves and who decides, the workflow; one
  agent's own job, that agent's file.
- A line checked by reading the code or text the project keeps is about
  its shape, and goes by how far it holds, widest first: any project, a
  shape; this whole project, a convention; one block, its README; one
  piece of code, a why-comment beside it, or a one-line doc on a piece
  other code uses.
- A brief or draft holds only work to do; what must outlast the work
  goes to its home before the work closes.
- Memory holds only the operator's preferences and lessons met while
  working, never a line a home above already holds.
- A line that fits two homes goes in the wider one; the narrower one
  never repeats it. A line about both behaviour and shape is split in
  two.
